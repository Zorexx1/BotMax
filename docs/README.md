# Люми

Бот для MAX, который отвечает на вечный школьный вопрос «зачем мне это учить». Ученик пишет тему,
Люми объясняет её на уровне его класса, а потом предлагает проверить тему в квесте по его интересам:
накопить на скин со скидкой и налогом, рассчитать зарядку электросамоката, закрыть кредит на сетап
для стрима. Пройти этап можно, только применив тему. Тексты и задачи пишет GigaChat, а второй запрос
перерешивает каждый квест и тест, прежде чем их увидит ученик.

Для кого: школьники с 1 по 11 класс, взрослые, которые подтягивают предмет, и учителя. Учитель
заводит класс, ученики вступают по коду, учитель задаёт тему, и квест приходит всему классу.

## Что умеет

- Объясняет тему под класс, от 1–4 класса до ЕГЭ. Первая фраза сразу отвечает на вопрос
  («Фотосинтез - это...»), в конце Люми предлагает уточнить, что интересно. Формулы обычным текстом
  (Φ = L·I, x², √x), MAX не показывает LaTeX.
- Ответ начинает появляться сразу и дописывается в том же сообщении. Кнопки под ответом: квест,
  свой сюжет, проще, подробнее, пример, «зачем это мне», битва с боссом, «объясню сам».
- Квесты из трёх этапов с подсказками, звёздами и разбором. В точных науках этапы - задачи,
  в истории, языках и т.п. - выбор с обоснованием.
- Битва с боссом: три вопроса на понимание. Режим «Учитель»: ученик сам объясняет тему, Люми
  оценивает понимание и задаёт уточняющий вопрос.
- Задача дня, одна на день. Через день она на тему, где ученик чаще ошибается.
- Разбор задания по фото.
- Опыт, 20 уровней, достижения с тремя ступенями, серия дней. Награды только за то, что решил сам:
  после «Разбора» задача не засчитывается, повтор пройденного квеста идёт без опыта, скопированный
  текст в «Учителе» не оценивается, за одно и то же по одной теме опыт дают ограниченно.
- Сложность (база / продвинутый / профи) подстраивается по результатам.
- Классы для учителя: задания, отчёт, кабинет на сайте, выгрузка CSV.
- Кабинет ученика в чате (`/me`) и на сайте, который можно поставить на телефон как приложение:
  уровень, серия, все разобранные темы с отметкой «получается / стоит повторить», достижения,
  рейтинг класса.
- Страница метрик для админа: возвращаемость, доходимость квестов, растёт ли точность с первой
  попытки. По ним видно, есть ли от бота польза.

Команды: `/start`, `/help`, `/menu`, `/quest`, `/random`, `/daily`, `/boss`, `/teach`, `/practice`,
`/why`, `/analyze`, `/me`, `/class`, `/play КОД`, `/new`, `/filter`, `/cancel`.

## Запуск

ВАЖНО: БОТ УЖЕ ЗАПУЩЕН НА СЕРВЕРЕ И ГОТОВ К РАБОТЕ, но если нужно запустить у себя - инструкции ниже.

В репозитории три папки:

- `docker/` - всё, из чего собирается Docker-образ: `Dockerfile`, `compose.yaml`, код бота,
  картинки, тесты;
- `requirements/` - `requirements.txt` со всеми библиотеками и их версиями;
- `docs/` - этот README.

```bash
git clone https://github.com/Zorexx1/BotMax
cd BotMax
cp docker/.env.example docker/.env    # вписать MAX_BOT_TOKEN и GIGACHAT_CREDENTIALS
```

### Docker

Собрать образ и запустить контейнер (из корня репозитория):

```bash
docker build -f docker/Dockerfile -t botmax .
docker run -d --name botmax --restart unless-stopped --env-file docker/.env \
  -p 8080:8080 -v botmax-data:/app/data botmax
```

То же через compose, так удобнее обновлять. Все команды `docker compose` запускаются из папки
`docker` (или из корня с ключом `-f docker/compose.yaml`):

```bash
cd docker
docker compose up -d --build
docker compose logs -f bot
```

Обновление. После изменения кода или `.env` контейнер надо пересоздать, `restart` новый `.env`
не подхватывает:

```bash
cd BotMax                    # корень репозитория
git pull
cd docker
docker compose up -d --build --force-recreate
```

Данные (SQLite) лежат в docker-томе и переживают пересборку.

### Без Docker, из командной строки

Python 3.12:

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements/requirements.txt
cd docker
python main.py
```

### Проверка ключей

```bash
python doctor.py            # из папки docker, или: docker compose run --rm bot python doctor.py
python doctor.py --quest    # ещё и собрать пробный квест (тратит токены)
```

Проверяет ключ GigaChat, сеть, доступные модели и задан ли токен MAX. Ключи не печатает.

### Что есть в docker/.env

- `MAX_BOT_TOKEN` - токен бота.
- `GIGACHAT_CREDENTIALS` - Authorization Key из кабинета GigaChat (около 100 символов, на конце `==`).
- `GIGACHAT_MODEL` - модель для коротких ответов, `GIGACHAT_QUEST_MODEL` - для объяснений, квестов
  и боссов. У нас это `GigaChat-2` и `GigaChat-2-Max`.
- `WEB_BASE_URL` - адрес кабинета, например `http://IP:8080`. Без него кнопки кабинета не показываются.
- `ADMIN_IDS` - MAX ID тех, кому доступны `/stats` и страница метрик.
- `POOL_TARGET` - сколько готовых квестов держать в запасе, чтобы «Удиви меня» и задача дня
  открывались сразу. 0 - не готовить (экономит токены).
- `WEBHOOK_URLS`, `WEBHOOK_SECRET` - вебхуки, см. ниже.

Остальное описано в `docker/.env.example`.

### HTTPS

Кабинет работает и по `http://IP:8080`, но с https его можно поставить на телефон как приложение
и браузер не ругается. Бесплатное имя даёт sslip.io (IP через дефисы), сертификат Caddy получит сам:

```bash
# в docker/.env
WEB_DOMAIN=203-0-113-10.sslip.io
WEB_BASE_URL=https://203-0-113-10.sslip.io
WEB_PUBLISH=127.0.0.1:8080
```

```bash
cd docker
docker compose --profile https up -d --build --force-recreate
```

На сервере должны быть открыты порты 80 и 443. Если https включён, при обновлении тоже добавляйте
`--profile https`, иначе Caddy не пересоздастся.

Мини-приложение MAX не делали: его адрес настраивается только на партнёрской платформе MAX,
а у конкурсного бота есть только токен. Поэтому `/me` в чате работает как маленькое приложение
с вкладками в одном сообщении, а полноценный кабинет открывается на сайте.

## Интеграции

- **JSON API.** `GET /api/v1/me`, `GET /api/v1/class/КОД`, `GET /api/v1/metrics`. Доступ по той же
  подписанной ссылке, что выдаёт бот (`?t=...`), учитель видит только свои классы.
- **CSV.** `/teacher/КОД.csv` - результаты класса для Excel или электронного журнала.
- **Вебхуки.** Бот сам отправляет итоги в любую внешнюю систему: журнал, LMS школы, Google-таблицу
  через Apps Script, CRM. Адреса через запятую в `WEBHOOK_URLS`. События: `quest_done`, `daily_done`,
  `boss_done`, `teach`, `assignment_done`, `onboarded`.

  ```json
  {"event": "quest_done", "user": 123, "nick": "Нео", "group": "8–9 класс",
   "topic": "проценты", "value": 0.78, "ts": 1700000000}
  ```

  Если задан `WEBHOOK_SECRET`, в заголовке `X-Lumi-Signature` приходит HMAC-SHA256 от тела.
  Проверка на стороне получателя:

  ```python
  hmac.compare_digest(hmac.new(secret.encode(), body, hashlib.sha256).hexdigest(), signature)
  ```

  При ошибке сервера бот повторяет запрос до трёх раз, ученик при этом ничего не ждёт.
- **GigaChat** подключён через официальный SDK, модели меняются в `docker/.env`.

## Если что-то не работает

Команды ниже - из папки `docker`.

`docker compose logs bot | grep GigaChat` - при старте бот пишет, видит ли он GigaChat, и если нет,
то почему.

- `ConnectError ... ngw.devices.sberbank.ru:9443` - сервер не в России или закрыт исходящий порт 9443.
- `HTTP 400 ... Can't decode 'Authorization'` - в `GIGACHAT_CREDENTIALS` не тот ключ. Нужен
  Authorization Key, а не Client Secret.
- `HTTP 401` - ключ не принят, скопировать заново. `HTTP 402` - кончились токены в пакете.
- `HTTP 429` - тариф не держит столько запросов сразу. Бот повторяет запрос сам и переходит
  на запросы по одному. Можно сразу поставить `GIGACHAT_PARALLEL=1`.
- Не собирается квест или босс - причина есть в логе:
  `docker compose logs bot | grep -E "отклонён|Проверка"`.

## Как устроен код

Всё лежит в `docker/`:

- `main.py` - точка входа. `func.py` - сценарии бота и обработка событий MAX.
- `answers.py` - всё про GigaChat: промпты, разбор и проверка квестов и тестов, очередь запросов,
  повторы при ошибках.
- `game.py` - опыт, уровни, достижения, серии, сложность, темы.
- `storage.py` - SQLite: профили, квесты, запас квестов, события, классы, задания.
- `web.py` - кабинеты, метрики и API. `analytics.py` - метрики. `hooks.py` - вебхуки.
- `ui.py` - кнопки и оформление. `tex.py` - формулы из LaTeX в обычный текст.
- `media.py` - фото заданий. `texts.py` - тексты бота и темы по классам.
- `content/offline_quests.json` - запасные квесты, если GigaChat недоступен.
- `assets/` - картинки бота и иконки сайта.

Новая функция обычно - это команда или кнопка в `func.py`, промпт в `answers.py` и, если надо,
поле в профиле (`game.py`). Хранилище, веб и интеграции от этого не меняются.

## Тесты

Сеть и ключи не нужны, запускать из папки `docker`:

```bash
python -m unittest discover -s tests
```

Проверка бота целиком: поднимаются поддельные MAX и GigaChat, запускается настоящий `main.py`,
и два «ученика» проходят знакомство, тему, квест, задачу дня, босса, кабинет, сбой GigaChat,
тариф с одним потоком и перезапуск:

```bash
python tests/e2e_check.py                    # бот запускается рядом
python tests/e2e_check.py --docker botmax    # бот в собранном образе
```

## Данные

Бот работает только в личке. В GigaChat уходят класс, интересы, позывной, уровень, слабые темы
и последние сообщения, ID и имя не передаются. Учитель видит имя ученика и результаты только
своего класса, и только если ученик сам вступил в класс по коду. Фото не сохраняются.
